# Cutaway doctrine — the next phase

*2026-09-07 · DOCTRINE department · rulings, not suggestions.*

## 1. The doctrine, one page

**What Cutaway is.** The record of a working day that a freelance editor can put in
front of a client without flinching. It is not a measurement instrument; it is an
evidence file that happens to count seconds.

**What it refuses to be.** A productivity tracker. A coach. A service. A guess with
a confident face. A thing you configure before it is correct.

**The four tests.** Every future feature passes all four or it is not built.

| Test | The question | Fails today |
|---|---|---|
| **Provenance** | For any number the app shows or exports, can it name the sessions behind it and mark each *tracked* or *entered*, in ≤2 clicks? | Render exemption (see §2) |
| **Consequence** | Does this happen because they worked, or because they configured something? A feature that needs a setting to be right is wrong by default. | 6 of 15 Settings controls |
| **Default** | Ship the value that is right, with no way to change it — unless a *contract* (not a taste) can make the other value correct. | Same 6 |
| **Silence** | Does the app get quieter? Cutaway interrupts for exactly two things. A third must replace one. | — |

**The hard evidence behind tests 2 and 3.** The owner's real preferences domain
(`com.vaneickelen.cutaway`) holds only window frames and app-written state
(`lastBackupAt`, `manuallyPaused`, `didShowPermissionsPrimer`,
`accessibilityOfferDismissed`, `didMigrateFromResolveTimer`). **Not one user choice.**
Fifteen controls, zero used. That is not contentment with the defaults — that is
months of building rooms nobody enters.

## 3. "So I know exactly how much to charge"

**"Exactly" is not a precision claim. It is a provenance claim.** Cutaway does not
become more honest by measuring in finer increments. It becomes more honest by being
able to say, for every number, where it came from and *who decided it*.

For the sentence to be literally true, five things must hold:

| Claim inside the sentence | What must be true | Today |
|---|---|---|
| "exactly" | No rule bills a second on machine evidence alone | ✗ — render exemption. Fix: §2 #1 |
| "exactly" | Every second on the invoice has a named cause that survives to the export | ◐ — `adjusted_hours` marks *who*, nothing records *why* (anchor / satellite / bridge) |
| "how much" | The displayed number is the invoiced number: rate history, round-once, locale-pinned | ✓ — this is the moat; do not touch it |
| "I know" | Given any figure a client questions, the owner can reconstruct it | ◐ — session rows exist; no artefact a client can hold |
| "I know" | The number is the same tomorrow | ✓ since 1.3.2 — and this is why the store bug outranked every feature |

This is why **no AI categorisation, ever**. The category sells precision and destroys
provenance: an AI-drafted timesheet is a number with a confident face and no author.
90 % of people say they don't trust AI with their data ([Malwarebytes, Mar 2026](https://www.malwarebytes.com/blog/privacy/2026/03/90-of-people-dont-trust-ai-with-their-data)),
52 % are now more concerned than excited about AI in daily life, up from 37 % in 2021
([Pew, via banthebots](https://www.banthebots.org/ai-backlash/)), and the billing-side
verdict is blunt: a polished wrong number is worse than an obvious one, because it
gives a false sense of security ([MASSIE](https://massietaxcredits.com/resources/articles/ai-rd-tax-credit-risks/)).
Rize is marked down precisely for AI-shaped bulk — "settings overwhelming", client
layer "an add-on" ([Efficient App](https://efficient.app/apps/rize)). Timemator is
praised as "no-nonsense" at $39 one-time ([timemator.com](https://timemator.com/)).
That is the cut line: premium Mac utilities cut by *removing decisions the user must
make*, not by removing capability — and the 2025-26 market punishes the opposite,
with every subscription conversion in this category drawing 1-star reviews
([BreezeKit](https://breezekit.app/en/articles/mac-subscription-fatigue), [Setapp](https://setapp.com/app-reviews/app-monetisation-strategies)).

It is the Provenance test made visual, and it is why the reclaim prompt stays dead. | Drag-to-create. Notes — revisit only as a *day* description feeding the PDF's line text. |

integrations/API/Zapier · rounding rules · the reclaim prompt.

## 5. Two decisions that now look wrong

**Decision 1 — no Apple Developer Program.** The premium audit said macOS 26 trashes
ad-hoc-signed downloads. Confirmed and worse: Sequoia already removed the control-click
bypass ([iDownloadBlog](https://www.idownloadblog.com/2024/08/07/apple-macos-sequoia-gatekeeper-change-install-unsigned-apps-mac/)),
and Tahoe reports these apps as "damaged … move to Trash"
([swissmacuser](https://swissmacuser.ch/fix-macos-tahoe-app-is-damaged-and-cant-be-opened-move-trash/)).
The doctrine consequence is not distribution — it is that **the ad-hoc signature also
drops TCC grants on every rebuild**, so the owner's own Accessibility permission keeps
evaporating. Ruling: the $99 stays optional, but `GOALS.md`'s **R-INSTALL "PROVEN" is
now false** and the README must stop selling `brew install --cask` as a working path
on macOS 26. Say what it is: build from source, or `--no-quarantine`, and why.

**The pill's tally light, on macOS 26.** The menu bar is transparent by default in
Tahoe ([Six Colors](https://sixcolors.com/post/2025/09/macos-26-tahoe-review-power-under-glass/)) —
Liquid Glass is a material change, not an API break, so the pill still works, but the
green/amber/red border now renders over arbitrary wallpaper
([AppleInsider](https://appleinsider.com/articles/25/06/11/liquid-glass-is-more-than-skin-deep-on-macos-tahoe)).
That border is the app's only always-visible truth signal. INTERFACE owns this.
