# Engineering and distribution: what professional Mac apps do
*Generated 2026-09-05 | Sources: 46 | Confidence: high for distribution/Sparkle/Gatekeeper (Apple docs + repos), medium for performance norms (Apple guidance is old but unchanged), low for memory-footprint norms (insufficient data)*

## Executive summary
Cutaway's ad-hoc signature is now its biggest professional gap: since macOS 15 the right-click → Open bypass is gone; users must fail a launch, dig into System Settings and authenticate [Apple](https://developer.apple.com/news/?id=saqachfa) [Sweetwater](https://www.sweetwater.com/sweetcare/articles/macos-security-warnings-and-gatekeeper-de-mystified/), and on macOS 26 an ad-hoc-signed quarantined app is sent to the Trash unless the user has already lowered Gatekeeper to "Anywhere" [Eclectic Light](https://eclecticlight.co/2026/08/11/how-can-you-run-code-that-hasnt-been-notarised/). The fix costs $99/year [Apple](https://developer.apple.com/programs/whats-included/) and one CI job (`notarytool submit --wait` + `stapler`) [Apple](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow). Every surveyed ≥10k-star Swift menu-bar app ships Developer-ID + Sparkle (or its own updater) plus a Homebrew cask; none ships crash telemetry. The Mac App Store is a poor fit: sandbox-mandatory, and `fuscript` spawning plus the "no helper processes after quit" rule would break or invite rejection [Apple](https://developer.apple.com/app-store/review/guidelines/). At 5.5k lines the only structural win is a UI-free core package with its own tests. The 1 Hz timer is fine with ≥10% tolerance and `NSWorkspace` notifications for app changes.

## 1. Distribution and trust
**Developer ID + notarization.** Membership is 99 USD per year and yields a Developer ID [Apple](https://developer.apple.com/programs/whats-included/). Notarization is an automated malware scan, "not App Review", usually done "in less than an hour"; the service publishes the ticket online and you staple it so Gatekeeper works offline [Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). Command-line flow: `xcrun notarytool submit --wait`, then `xcrun stapler staple App.app`; a ZIP can be notarized but not stapled—staple the .app, then re-zip [Apple](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow). `altool` has been dead since Nov 2023 [Apple](https://developer.apple.com/developer-id/). Notarization requires Hardened Runtime; Sparkle's docs specifically warn that hand-rolled `codesign` over Sparkle.framework strips XPC entitlements—use `xcodebuild -exportArchive` [limpid release.yml](https://github.com/nek0der/limpid/blob/main/.github/workflows/release.yml).

**Gatekeeper on macOS 15/26.** Apple: "users will no longer be able to Control-click to override Gatekeeper… They'll need to visit System Settings > Privacy & Security" [Apple](https://developer.apple.com/news/?id=saqachfa) [Apple Support](https://support.apple.com/en-us/102445). In practice: failed launch → Settings → "Open Anyway" within an hour → admin password → relaunch [Sweetwater](https://www.sweetwater.com/sweetcare/articles/macos-security-warnings-and-gatekeeper-de-mystified/). On a fresh Tahoe 26.6.1 VM an ad-hoc-signed quarantined app "was directed to the Trash"; it only runs if the user has enabled "Anywhere" (which needs `sudo spctl --master-disable`) or strips quarantine—unsigned code "has never been allowed in Apple silicon Macs" [Eclectic Light](https://eclecticlight.co/2026/08/11/how-can-you-run-code-that-hasnt-been-notarised/). Homebrew installs sidestep this (the cask drops quarantine); the GitHub zip does not.

**Sparkle 2.** Run `generate_keys` once (EdDSA private key in Keychain, public key → `SUPublicEDKey` in Info.plist), set `SUFeedURL`, keep `CFBundleVersion` monotonic, and let `generate_appcast` sign archives and emit `appcast.xml` + deltas; `.md` release notes are supported since 2.9 [Sparkle](https://sparkle-project.github.io/documentation/). Opt into `SUVerifyUpdateBeforeExtraction` (2.7.3+) and `SURequireSignedFeed` (2.9+) for signed feeds; key rotation is possible only when Developer-ID-signed [Sparkle](https://sparkle-project.org/documentation/customization/). Serve over HTTPS; GitHub Releases + a gh-pages `appcast.xml` is the common zero-cost host [limpid](https://github.com/nek0der/limpid/blob/main/.github/workflows/release.yml) [Mercury](https://github.com/neolee/mercury/blob/8df4c8d40437c2b513e20d5f542e46b22a8deac9/.github/workflows/release.yml). Sparkle would be Cutaway's only network call—document it and make it user-controllable.

**Homebrew coexistence.** Add `auto_updates true` when the app has an in-app updater; Homebrew then skips it on `brew upgrade` unless `--greedy`, preventing double updates [Cask Cookbook](https://docs.brew.sh/Cask-Cookbook) [homebrew-cask #207047](https://github.com/Homebrew/homebrew-cask/pull/207047). Use `livecheck { strategy :sparkle }` pointing at the appcast [homebrew-cask #170994](https://github.com/Homebrew/homebrew-cask/issues/170994).

**Mac App Store?** Guideline 2.4.5 requires sandboxing, Xcode-only packaging, and forbids spawning "processes that continue to run without consent after a user has quit the app" [Apple](https://developer.apple.com/app-store/review/guidelines/). Under the sandbox a child launched via `Process`/`posix_spawn` must carry `com.apple.security.inherit` and inherits the parent's sandbox [Apple](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html); `fuscript` lives in Resolve's bundle, is not yours to entitle, and needs Resolve's IPC—expect failure. Launching arbitrary executables from a sandbox is "a violation of the sandbox model" [StackOverflow](https://stackoverflow.com/questions/12594380/how-to-launch-another-process-in-sandbox-on-mac). Reading `NSWorkspace.frontmostApplication` and `CGEventSource.secondsSinceLastEventType` are read-only queries with no entitlement listed [Apple](https://developer.apple.com/documentation/coregraphics/cgeventsource/secondssincelasteventtype(_:eventtype:)); evidence they work sandboxed is indirect (SaneClip's MAS build only loses synthetic key events [SaneClip](https://github.com/sane-apps/SaneClip)). Sparkle must be replaced by App Store updates. Verdict: skip MAS, or ship a reduced no-Resolve build later.

## 2. Reliability tooling without telemetry
- **MetricKit** is available on macOS 12+; "Diagnostic reports arrive immediately in… macOS 12 and later", and macOS 27 adds an async-sequence `MetricManager` [Apple](https://developer.apple.com/documentation/metrickit). It is on-device, zero-dependency, and privacy-respecting: subscribe, persist `MXCrashDiagnostic` to disk, show them in a Settings "Diagnostics" pane the user can copy—no upload needed [Soarias](https://soarias.com/swiftui/how-to-build-crash-reporting/). Call stacks are unsymbolicated; keep dSYMs, or symbolicate on-device with ChimeHQ's Meter [Meter](https://github.com/stacksift/Meter). Payloads never arrive in Simulator/Debug [Soarias](https://soarias.com/swiftui/how-to-build-crash-reporting/).
- **Uncaught NSExceptions**: set `NSApplicationCrashOnExceptions=YES` so the app crashes cleanly instead of continuing with corrupt state [MeterReporter](https://github.com/ChimeHQ/MeterReporter).
- **What the exemplars do**: Stats states "does not collect any telemetry or analytics", its only network calls are update checks, and crash handling is "update, then search issues, then file one" [Stats README](https://github.com/exelban/stats). Ice keeps a FREQUENT_ISSUES.md; Rectangle keeps SECURITY.md and CONTRIBUTING.md; all use GitHub issue templates [Ice](https://github.com/jordanbaird/Ice) [Rectangle](https://github.com/rxhanson/Rectangle). None of the seven surveyed embeds Sentry/Crashlytics. An "opt-in only" alternative that files GitHub Issues directly exists but embeds a token in the binary—rejected for a privacy-first app [git-beacon-mac](https://github.com/marcops/git-beacon-mac).
- **Release automation**: tag-driven GitHub Actions on `macos-26`: import Developer ID .p12 into a throwaway keychain → archive/export → notarize+staple → `create-dmg` → notarize DMG → `generate_appcast --ed-key-file -` → push appcast to gh-pages → `gh release create --generate-notes` [limpid](https://github.com/nek0der/limpid/blob/main/.github/workflows/release.yml) [Mercury](https://github.com/neolee/mercury/blob/8df4c8d40437c2b513e20d5f542e46b22a8deac9/.github/workflows/release.yml) [gist](https://gist.github.com/rampatra/08c6e895e051f35c9cb05f3789f243e0). Stats does the same locally via Makefile (`notarytool --keychain-profile`, `create-dmg`, dSYM archiving) [Stats Makefile](https://github.com/exelban/stats/blob/master/Makefile); KeyboardCowboy runs `generate_appcast` from the SwiftPM Sparkle artifact [create_release.sh](https://github.com/zenangst/KeyboardCowboy/blob/main/create_release.sh). Nobody surveyed uses fastlane.

## 3. Performance and energy for a 1 Hz menu-bar app
- **Timer tolerance**: "set the tolerance to at least 10% of the interval… Even a small amount of tolerance has significant positive impact on the power usage"; repeating timers do not drift because the next fire is computed from the original schedule [Apple](https://developer.apple.com/documentation/foundation/timer). For GCD timers the `leeway` argument feeds Timer Coalescing; `dispatch_timer_strict` opts out and should be avoided [Apple PDF](https://www.apple.com/media/us/osx/2013/docs/OSX_Power_Efficiency_Technology_Overview.pdf). `DispatchSourceTimer` needs no run loop, which matters if the engine moves off the main actor [Cocoa with Love](https://www.cocoawithlove.com/blog/2016/07/30/timer-problems.html).
- **Events over polling**: "some apps use timers to poll for state changes when they should respond to events instead" [Apple](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html). Use `NSWorkspace.didActivateApplicationNotification` (or the Swift-concurrency `DidActivateApplicationMessage`) for frontmost-app changes; the `userInfo` carries the `NSRunningApplication` [Apple](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification). Keep the timer only for idle-time accounting and the running clock.
- **Idle time**: `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: kCGAnyInputEventType)` is a single system query, macOS 10.4+, no permission prompt [Apple](https://developer.apple.com/documentation/coregraphics/cgeventsource/secondssincelasteventtype(_:eventtype:)). Per-call cost: insufficient data; at 1 Hz the timer wake dominates.
- **App Nap**: a menu-bar app without visible window updates is a candidate; App Nap throttles timers and priority but "does not necessarily save energy"—reach idle proactively [Apple](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/AppNap.html). Stop the timer when no session is running.
- **Measuring**: Xcode Energy gauge should be "zero energy impact" when the user isn't interacting; Activity Monitor "Idle Wake Ups" column and `timerfires -s <pid>` show timer wakes; `powermetrics --samplers tasks` gives per-process wakeups and CPU [Apple](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/MonitoringEnergyUsage.html) [powermetrics(1)](https://ss64.com/mac/powermetrics.html). Target: >1 wake/s while idle is a bug per Apple [Apple](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html).
- **Launch time**: Apple gives no macOS millisecond target; guidance is to profile with the Instruments App Launch template, limit embedded third-party frameworks (each adds dyld work—Sparkle will be one), avoid static initializers, and defer persistent-store setup to first use [Apple](https://developer.apple.com/documentation/xcode/reducing-your-app-s-launch-time). Memory-footprint norms for menu-bar apps: insufficient data (no published benchmark found).

## 4. Code structure and SwiftData
- **When packages pay off**: "If your app is still a single target with a few dozen files, you probably don't need this yet"; split when builds slow, small changes cascade, or you can't preview/test a view without the whole stack [Kyle Browning](https://kylebrowning.com/posts/modularizing-swift-apps-with-spm/). The layering rule: Core packages import only Foundation-level packages, Feature packages import Core, never each other [DECODE](https://decode.agency/article/project-modularization-swift-package-manager/) [Dashlane](https://www.dashlane.com/blog/organize-swift-packages). For 5.5k lines that means one `CutawayCore` package (session math, idle rules, Resolve bridge protocol, export) testable via `swift test` without AppKit.
- **Swift 6 + @Observable + timer**: keep the model `@MainActor` (or set `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, SE-0466) and use `@concurrent` only for genuine background work [Blake Crosley](https://blakecrosley.com/blog/swift-6-2-concurrency-in-practice) [Hacking with Swift](https://www.hackingwithswift.com/swift/6.0/concurrency). Timer callbacks then mutate observable state on the main actor with no locks; put pure "tick(now:idle:frontmost:) -> Effect" logic in a `Sendable` struct so tests don't need a timer.
- **SwiftData pitfalls**: wrap every `@Model` in a `VersionedSchema` from v1 and version every model, even unchanged ones, or staged migration fails with "unknown model version" [Indie Spark](https://indiespark.org/programming/how-to-keep-swiftdata-from-crashing-your-app-on-modelactor-release-and-staged-migrations/); do not declare a V2 for inline-default additions—it triggers "Duplicate version checksums" [Blake Crosley](https://blakecrosley.com/blog/swiftdata-migrations-guide); custom `didMigrate` closures must `save()` or re-run every launch [ibid](https://blakecrosley.com/blog/swiftdata-migrations-guide). Build the `ModelContainer` once and keep it alive; hand `persistentModelID`s, not objects, across `@ModelActor` boundaries [Indie Spark](https://indiespark.org/programming/how-to-keep-swiftdata-from-crashing-your-app-on-modelactor-release-and-staged-migrations/). Cutaway's launch-time backup rotation is the right mitigation for the "silent no-op migration" failure mode [Smart Kiitös](https://smartkiitos.com/blog/local-first-ios-swiftdata-cloudkit/).
- **iCloud sync**: needs the iCloud + Background Modes capabilities (paid membership), all relationships optional, no unique constraints, and a production CloudKit schema that is additive-only forever [Apple](https://developer.apple.com/documentation/swiftdata/syncing-model-data-across-a-persons-devices). Conflicts are last-writer-wins with no SwiftData-level hooks; budget ~30% extra time [Smart Kiitös](https://smartkiitos.com/blog/local-first-ios-swiftdata-cloudkit/); use separate container IDs per build config [Indie Spark](https://indiespark.org/programming/how-to-keep-swiftdata-from-crashing-your-app-on-modelactor-release-and-staged-migrations/). It would also contradict "no network calls ever". Not recommended.

4. **Set `timer.tolerance = 0.1`+, stop the timer when no session runs, switch frontmost detection to `didActivateApplicationNotification`; verify 0 idle wakes with `timerfires`/`powermetrics`** [Apple](https://developer.apple.com/documentation/foundation/timer) [Apple](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification). Effort S; free.

8. **Do not pursue Mac App Store or CloudKit** — sandbox breaks `fuscript`, and CloudKit contradicts the privacy promise [Apple](https://developer.apple.com/app-store/review/guidelines/) [Apple](https://developer.apple.com/documentation/swiftdata/syncing-model-data-across-a-persons-devices). ## Methodology
Searches via Exa, Firecrawl and WebSearch (2026-09-05); Apple developer pages fetched with Firecrawl because they are JS-rendered. Exemplar facts (stars, last push, workflows, directory layout, Sparkle references in `project.pbxproj`, `.lproj` counts) were read directly from the GitHub API and raw files, not from third-party lists. Preference given to sources ≤18 months old; Apple's Energy Efficiency Guide (2016) and the Mavericks power PDF (2013) are older but remain Apple's only primary guidance on timer tolerance, coalescing and App Nap. Claims marked "insufficient data" (idle-query cost, memory norms, sandbox behaviour of read-only CG/NSWorkspace queries) had no primary source. Exa rate-limited mid-session; remaining queries used WebSearch/Firecrawl. Not verified: any behaviour on a physical macOS 26 machine.
